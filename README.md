# فیلم با هم (Movie Together)

برنامهٔ تماشای همزمان فیلم برای دو نفر، همراه با چت صوتی زنده. روی موبایل (Android Chrome) و کامپیوتر کار می‌کند و به‌صورت PWA قابل نصب است. (English notes: `README.en.md`)

## ۱. وضعیت آزمایش‌ها (صادقانه)

| مورد | وضعیت |
|---|---|
| منطق اتاق و سرور (۱۶ تست خودکار: ورود دو نفر، پر بودن اتاق، play/pause/seek، ورود دیرهنگام، ورود مجدد، جداسازی اتاق‌ها) | ✅ اجرا و قبول شد |
| کلاینت واقعی در Chromium واقعی با WebRTC واقعی (۴۰ بررسی: صدا، همگام‌سازی، قطع و وصل، رفرش، PWA، آفلاین) | ✅ قبول شد، اما با یک سرور آزمایشی که همان کد `socket.js` را اجرا می‌کند، نه با Socket.IO واقعی |
| اجرای `server.js` با Express و Socket.IO واقعی | ⚠️ اجرا نشد (در محیط ساخت اینترنت برای `npm install` نبود) |
| Android Chrome واقعی، دو گوشی واقعی، شبکهٔ موبایل، TURN | ❌ آزمایش نشد. فقط شبیه‌سازی اندازهٔ صفحه و User-Agent انجام شد |
| اشتراک صفحه (Screen Share) | فقط در Chromium رومیزی آزمایش شد. روی اندروید معمولاً وجود ندارد |

پس اولین کاری که باید بکنید اجرای `npm install` و `npm start` و آزمایش با دو گوشی است (بخش ۴).

## ۲. اجرا روی کامپیوتر خودتان
1. Node.js نسخهٔ ۲۰.۶ یا بالاتر را از nodejs.org نصب کنید.
2. در ترمینال، داخل پوشهٔ پروژه:
   ```
   npm install
   npm start
   ```
3. آدرس http://localhost:3000 را در دو تب باز کنید. یکی «ساخت اتاق» را بزند و دیگری با لینک وارد شود.
4. اجرای تست‌ها: `npm test`

> میکروفون روی گوشی فقط با **HTTPS** کار می‌کند، پس برای گوشی از بخش ۴ یا ۵ استفاده کنید.

## ۳. گذاشتن روی اینترنت (Render)، پیشنهاد اصلی
فرانت‌اند و بک‌اند یک سرویس‌اند و HTTPS/WSS خودکار است.
1. در github.com حساب بسازید و یک مخزن (repository) جدید بسازید، بعد کل پوشهٔ پروژه را در آن آپلود کنید (`node_modules` و `.env` نباید باشند).
2. در render.com با حساب GitHub وارد شوید، **New → Blueprint** را بزنید و همان مخزن را انتخاب کنید (فایل `render.yaml` همه‌چیز را تنظیم می‌کند).
3. منتظر بمانید تا Deploy تمام شود. آدرسی مثل `https://movie-together-xxxx.onrender.com` می‌گیرید.
4. آن آدرس را روی گوشی باز کنید، اتاق بسازید، «کپی لینک دعوت» را بزنید و برای دوستتان بفرستید.

**محدودیت‌ها:**
- پلن رایگان بعد از حدود ۱۵ دقیقه بی‌کاری می‌خوابد (اولین ورود کند است) و اتاق‌ها پاک می‌شوند. برای سرور همیشه‌روشن، در `render.yaml` مقدار `plan: starter` را بگذارید (هزینه دارد).
- فقط **یک** نمونه (instance) اجرا کنید، چون اتاق‌ها در حافظه‌اند.
- جایگزین‌ها: Railway یا Fly.io (فایل `Dockerfile` آماده است).

## ۴. آزمایش با گوشی خودتان و گوشی دوستتان
1. آدرس عمومی (بخش ۳ یا ۵) را در Chrome اندروید باز کنید.
2. نام بنویسید، «ساخت اتاق»، اجازهٔ میکروفون را بدهید.
3. «کپی لینک دعوت» (یا Share) را بزنید و لینک را برای دوستتان بفرستید.
4. دوست شما لینک را باز می‌کند، نام می‌نویسد، «ورود به اتاق» را می‌زند و اجازهٔ میکروفون می‌دهد.
5. بالای صفحه باید «متصل» و «صدا وصل است» ببینید. **با هدفون** تست کنید تا اکو نشود.
6. لینک مستقیم یک فایل MP4/WebM بگذارید و «پخش برای هر دو» را بزنید. play، pause و seek را از هر دو طرف امتحان کنید.
7. برای نصب: منوی Chrome ← «Install app / افزودن به صفحهٔ اصلی».

## ۵. راه سریع برای امتحان امشب، بدون حساب کاربری (از روی کامپیوتر خودتان)
اگر کامپیوتر روشن بماند:
1. `npm start` را اجرا کنید.
2. در ترمینال دیگر: `cloudflared tunnel --url http://localhost:3000` (برنامهٔ cloudflared را از developers.cloudflare.com نصب کنید).
3. آدرس `https://….trycloudflare.com` که چاپ می‌شود لینک عمومی است و WebSocket را پشتیبانی می‌کند.

## ۶. تنظیمات سرور (متغیرهای محیطی)
| نام | لازم؟ | توضیح |
|---|---|---|
| `PORT` | خیر | را Render خودش می‌گذارد |
| `NODE_ENV=production` | توصیه می‌شود | هدایت http به https |
| `TURN_URLS` | برای پایداری صدا | مثلاً `turn:turn.example.com:3478,turns:turn.example.com:5349?transport=tcp` |
| `TURN_SECRET` | همراه TURN_URLS | رمز coturn (حالت `use-auth-secret`) |
| `TURN_USERNAME` / `TURN_CREDENTIAL` | جایگزین | اگر سرویس TURN آماده دارید |

هیچ رمزی در کد فرانت‌اند نیست. سرور هنگام نیاز، اعتبارنامهٔ موقت ۲۴ ساعته به کلاینت می‌دهد.

**STUN/TURN:** بدون TURN فقط از STUN عمومی گوگل استفاده می‌شود. این روی بسیاری از Wi‑Fi‌ها کار می‌کند، اما روی برخی اینترنت‌های موبایل (CGNAT) صدا وصل نمی‌شود. آن‌وقت یک VPS ارزان بگیرید و coturn نصب کنید (`use-auth-secret`، `static-auth-secret`، پورت‌های 3478 و 5349 و بازهٔ 49152–65535 باز باشند) و دو متغیر بالا را در Render بگذارید. هنگام اجرا اگر TURN تنظیم نباشد در لاگ سرور هشدار می‌دهد.

## ۷. سایت‌های فیلم و محدودیت‌ها
- بیشتر سایت‌ها (و تمام سرویس‌های دارای DRM) به‌خاطر `X-Frame-Options`، `CSP`، ورود به حساب و DRM اجازهٔ نمایش داخل iframe را نمی‌دهند. برنامه آدرس را امتحان می‌کند، اما **قول نمی‌دهد** که کار کند، و پخش داخل iframe **همگام نمی‌شود**.
- راه‌های پشتیبانی‌شده:
  1. **لینک مستقیم فایل** (`.mp4`, `.webm`) روی https. این تنها حالت کاملاً همگام است. سرور فایل باید اجازهٔ پخش بدهد.
  2. **اشتراک صفحه** از یک مرورگر رومیزی (Chrome/Edge/Firefox). صدای تب فقط در بعضی مرورگرها و سیستم‌عامل‌ها منتقل می‌شود. روی اندروید معمولاً این قابلیت نیست و برنامه همین را می‌گوید.
  3. **هر دو نفر همان سرویس قانونی** را جداگانه باز کنند و با چت صوتی هماهنگ شوند (بدون همگام‌سازی خودکار).
- دور زدن DRM، پرداخت یا کنترل دسترسی پشتیبانی نمی‌شود.

## ۸. چیزهایی که هنوز ناقص است
- توقف خودکار هنگام بافر شدن ندارد (تا tick بعدی ممکن است کمی اختلاف بماند).
- تست خودکار روی Android Chrome واقعی و TURN انجام نشده.
- فایل `package-lock.json` ندارد (با اولین `npm install` ساخته می‌شود؛ آن را هم commit کنید).
- اتاق‌ها در حافظه‌اند: با ری‌استارت سرور پاک می‌شوند.

## ۹. چک‌لیست نهایی قبل از Deploy

**فایل‌هایی که باید آپلود کنید (ضروری):**
`package.json`، `server.js`، `socket.js`، `rooms.js`، `render.yaml` و کل پوشهٔ `public` (شامل `index.html`، `sw.js`، `manifest.webmanifest`، `icon.svg` و سه فایل `icon-*.png`).
اختیاری: `Dockerfile`، `.dockerignore`، `.gitignore`، `.env.example`، `README.md`، `README.en.md`، پوشهٔ `test`.
**هرگز آپلود نکنید:** `node_modules` و هر فایل `.env` واقعی (رمزها فقط در داشبورد Render وارد می‌شوند).

**تنظیمات Render:** Language/Runtime = Node، Build Command = `npm install`، Start Command = `npm start`، Health Check Path = `/healthz`، متغیر `NODE_ENV` = `production`، `NODE_VERSION` = `22`. اگر از Blueprint استفاده کنید همه خودکار از `render.yaml` پر می‌شود.

**اتصال دائمی نیست (پلن رایگان):** سرور بعد از حدود ۱۵ دقیقه بی‌کاری می‌خوابد. بیدار شدن تا یک دقیقه طول می‌کشد و اتاق‌ها هنگام خواب یا ری‌استارت (و هر بار Deploy تازه) پاک می‌شوند. برنامه در این حالت بعد از چند ثانیه پیام «سرور احتمالاً در حال بیدار شدن است» نشان می‌دهد و اگر اتاق از بین رفته باشد می‌گوید اتاق جدید بسازید. برای تماشای واقعی با دوست، ۱۰ دقیقه قبل خودتان آدرس را یک بار باز کنید تا سرور بیدار شود.

**هنوز تأیید نشده:** `npm install` و اجرای واقعی `server.js` با Express و Socket.IO (در محیط ساخت اینترنت نبود)، Android Chrome واقعی، TURN. فایل `package-lock.json` هم ساخته نشد و با اولین `npm install` روی کامپیوتر خودتان ساخته می‌شود؛ آن را هم آپلود کنید. Render بدون آن هم کار می‌کند.
